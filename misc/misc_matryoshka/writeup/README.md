# matryoshka（套娃图片）— Writeup

## 题目附件

`dist/` 下一个文件，资源管理器里显示为 `1.png`，双击打不开（无关联程序）。

## 解题链（共 5 层，每层五步）

### 1. 文件名 RLO 欺骗

`dir` / `ls` 拿到的真实文件名是 `gnp.1`，前面带一个不可见字符 U+202E（RIGHT-TO-LEFT OVERRIDE，UTF-8 字节 `E2 80 AE`）。它强制后续字符按从右到左渲染，于是 `gnp.1` 显示成 `1.png`。

- Windows 按最后一个 `.` 取真实扩展名 `.1`，无关联程序，所以双击打不开
- `glob("*.png")` 匹配不到任何文件
- 识破方法：十六进制查看文件名，或注意 `ls` 输出与资源管理器显示不一致

每解压一层都会再遇到一次（`2.gif` 实为 `fig.2`、`3.png` 实为 `gnp.3`……），显示的编号就是层号。

### 2. 图片 polyglot

`file` / 魔数识别：文件头是真实图片（PNG/GIF 混排，每层不同）。图片解码器读到各自的结束标记（PNG 的 IEND、GIF 的 trailer `0x3B`）就停，**尾部追加的字节全部忽略**——所以文件尾部可以再藏东西，图片本身仍能正常打开查看。

### 3. 三明治分离

十六进制查看图片尾部，大多数层的结构是：

```
[完整图片字节] + [MATRYOSHKA-CIPHER-FRAG i/5 + hex 碎片] + [ZIP]
```

**第 2 层例外**：尾部文本只有一句 `kipfel可爱捏，好看，爱看，多看`，没有明文碎片——按提示"多看"这个 GIF 本身：碎片藏在**全局色彩表的 LSB** 里。每个调色板条目 R/G/B 三字节各贡献最低 1 bit，连起来是 `MSK` 魔数 + 1 字节长度 + 数据，提取脚本几行就能写完（GIF 头 13 字节后就是全局色彩表）。调色板低位每通道只动 ±1，视觉完全无损。

ZIP 起点可以搜 `PK\x03\x04`，也可以用 EOCD 反推（`zip_start = eocd_pos - cd_size - cd_offset`，见 exp.py，更稳）。

### 4. ZIP 加密：三种层各不相同

- **层 1（伪加密）**：解压弹密码框，实际数据是明文。修复：把条目 local file header（`PK\x03\x04` 偏移 +6）和 central directory header（`PK\x01\x02` 偏移 +8）两处 GP flag 的 bit0 清零，解压即成功。
- **层 3（真加密）**：货真价实的 ZipCrypto。按伪加密清零 flag 后解压直接报 CRC/解压错误——数据真的锁了。**钥匙挂在锁上**：这层 zip 的 archive comment（明文可读，无需解压）里写的就是密码本身——KEY 碎片的 hex 字符串。
- **层 2、4、5（不加密）**：zip 干干净净，直接解压。

> 判断方法：看 GP flag bit0——为 0 就没加密直接解；为 1 先按伪加密修 flag 试，能开是伪加密，开不了是真加密。只有层 3 值得爆破？不——爆破是死路，密码近在眼前。

### 5. comment 取密钥碎片 + 解压下一层

解压软件详情页（7-Zip"注释"栏 / `unzip -z`）能看到 archive comment：

```
MATRYOSHKA-KEY-FRAG i/5
<hex>
```

对真加密层（3），这段 hex 同时是解压密码；对普通伪加密层，它只是密钥碎片。

**第 4 层是 kipfel 层**：comment 不再直接给明文，而是一段"密钥被 kipfel 吃掉"的动画——可见前缀逐行变短、吃掉的字符用点代替，最后只剩 `-` 和一串点，明文永远不完整：

```
你来晚啦，密钥已经被kipfel吃掉一些了>w<
9ecac694f5c7>
9ecac694f5c7-
9ecac694f5c-...
...
9-
-................
（看起来是空的一行）
```

最后一行"空行"里藏着完整密钥：零宽字符隐写。选中复制那一行会发现有内容，十六进制查看是一堆 `E2 80 8B / E2 80 8C`。解码规则：

- U+200B（ZWSP）= 0，U+200C（ZWNJ）= 1
- 每 4 个零宽字符按二进制转 1 个 hex 字符

动画行泄漏的可见前缀可以当解码结果的校验（解码错误立刻能发现对不上）。

解压得到一个内容为 hex 文本的文件（decode 后就是下一层 polyglot），文件名又是 RLO 假名，编号 +1。循环 5 层，直到解出 `END.txt`（到达最底层的提示）和 `prize.png`。

### 6. 碎片重组（KEY 是倒序配对的）

收集齐 5 段 CIPHER 碎片和 5 段 KEY 碎片后，直接按表面序号 `[i/5]` 各自拼接、XOR——**只会得到乱码**。

陷阱：每层 comment 标的序号和 CIPHER 一致（都是层号），但 KEY 的**内容**是错位的——除第 1 层外倒序配对：

| 层 | CIPHER | comment 里实际的 KEY |
|----|--------|---------------------|
| 1  | c₁     | k₁                  |
| 2  | c₂     | k₅                  |
| 3  | c₃     | k₄                  |
| 4  | c₄     | k₃                  |
| 5  | c₅     | k₂                  |

所以 CIPHER 按层序拼，KEY 要按层序 [1, 5, 4, 3, 2] 重排后再拼，然后逐字节 XOR（等长密钥的一次一密）：

```python
cipher = c1 + c2 + c3 + c4 + c5
key    = k1 + k5 + k4 + k3 + k2   # 即按层收集顺序拼接
flag = bytes(c ^ k for c, k in zip(cipher, key))
```

发现路径：XOR 出乱码 → 意识到 KEY 顺序不对 → 倒序是最自然的对称假设（或对 5 段 key 穷举排列，用结果可打印性/`hctf{` 前缀判断，120 种瞬间出）。

## 题目现在的完整格局

| 层 | 图片 | CIPHER 位置 | ZIP 加密 | KEY 位置 |
|----|------|------------|----------|----------|
| 1 | PNG | 尾部明文 | 伪加密 | comment 明文 |
| 2 | GIF | 调色板 LSB（台词指引） | 不加密 | comment（实为 k₅） |
| 3 | PNG | 尾部明文 | 真加密（密码=自己的 k₄） | comment（实为 k₄） |
| 4 | PNG | 尾部明文 | 不加密 | kipfel 吃密钥 → 零宽字符（实为 k₃） |
| 5 | PNG | 尾部明文 | 不加密 | comment（实为 k₂） |

最后：KEY 按倒序配对重组，与 CIPHER 逐字节 XOR 得 flag。

## 知识点清单

1. Unicode U+202E 文件名欺骗（显示名 vs 真实名 vs 真实内容格式三层信息不一致）
2. 图片尾部追加 polyglot（PNG IEND / GIF trailer 后数据被解码器忽略，多格式混排防写死魔数的脚本）
3. ZIP 结构：EOCD 定位、archive comment 藏数据
4. ZIP 伪加密 vs 真加密（GP flag bit0 两处修复 vs ZipCrypto 解密，同样弹密码框但判然两物；真加密层密码就挂在自己的 comment 里）
5. 零宽字符隐写（U+200B/U+200C 二进制编码，"被吃掉"的明文前缀可校验）
6. GIF 全局色彩表 LSB 隐写（调色板每通道 1 bit，MSK 魔数 + 长度头，台词"多看"指引）
7. hex 编码层（binwalk 认不出 hex 文本里的下一层魔数，自动递归提取失效）
8. 碎片配对错位（comment 序号是层号、KEY 内容倒序归属——表面序号拼 key 必得乱码）
9. 碎片分片 + OTP XOR 重组（缺任何一层都解不出，强制完整解链）

## 出题/验证工具

- `build.py`：生成器。`FLAG=hctf{...} python build.py` 重新出题（换 flag/换图改 `LAYERS`）
- `exp.py`：解题链 PoC，按选手视角步骤化打印全过程
- `verify.py`：出题自检（RLO 字节 / 图片完好 / 伪加密行为 / strings 短路 / 全层解码）
- `assets/`：每层图片素材（l1..l5 + 终点 prize），替换后重跑 build.py 即可
