# web_leakedkey

- **分类**：Web
- **难度**：简单
- **题型**：剧情向高校统一身份认证平台渗透（前端硬编码 RSA 私钥 + 密文解密）
- **附件**：无

## 题面

还是那个怎么都登不进去的统一身份认证平台。

上一题，你是不是漏看了一个很重要的东西，再去看看。

- 登录接口不是 SQL 注入题，任何账号密码都会返回「用户名或密码错误」
- 本题 flag 为解密出的管理员测试口令
- 走完上一题的老路，会在 doc.html 里顺手捡到一串像 flag 的东西——那是纪念品，不是答案

## 提示

1. 密文在本环境 doc.html 的「开发调试记录」一段——那扇 403 的门，上一题已经开过一次
2. RSA 的 n / e / d 都在手，解密只是一行 pow 的事

## 部署

```bash
docker build -t leakedkey ./src
docker run -d -p 58000:80 -e FLAG="hctf{xxx}" leakedkey
```

- 服务监听容器内 `0.0.0.0:80`（Nginx 网关 + FastAPI 后端同容器），宿主端口 `58000`
- **动态 flag**：平台向容器注入 `FLAG` 环境变量，启动时重播种把 flag 加密进
  doc.html 内的「拦截密文」（题内闭环，无跨题依赖）；未注入时使用代码内
  回退值（保持 `hctf{}` 格式）
- 本实例保留上一题（pathconfusion）同款的网关/后端解析差异
  （`/sc/..;/doc.html`）作为密文获取通道；doc.html 内原题1 flag 槽位放置
  静态诱饵 `fflag{...}`（判分不收）
- 本实例为三题赛题链的题2 切片，独立部署、独立可解（题3 槽位为无害占位符）
